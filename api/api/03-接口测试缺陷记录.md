> 被测系统：狂神の小社区（kuang_simple_bbs），`http://localhost:8080`

> 缺陷来源：Apifox 接口测试 → 场景二「安全-接口测试」执行结果 + 源码定位
> 缺陷总数：5 条（严重 2 条、一般 3 条）

|---|---|---|---|---|---|

## BUG-01 未登录访问发帖页返回 500

| 项 | 内容 |
|---|---|
| 缺陷编号 | BUG-01 |
| 所属模块 | 认证与权限 |
| 严重程度 | 严重 |
| 优先级 | 高 |
| 复现前置 | 清除浏览器/Apifox 全部 Cookie，处于未登录状态；后端服务正常运行 |
| 复现步骤 | 1. Apifox 中新建请求 `GET http://localhost:8080/blog/write`<br>2. 不携带任何 Cookie / 会话<br>3. 点击发送 |
| 预期结果 | 302 重定向到 `/toLogin`，用户被引导至登录页 |
| 实际结果 | 返回 **500 Internal Server Error**，服务端抛出空指针异常 |
| 影响 | 未登录用户通过直接输入 URL 或收藏夹访问时看到错误页，而不是被友好地引导登录；同时异常堆栈暴露了服务端内部信息 |
| 初步根因 | `blog/write` 是两级路径，未被 `SecurityConfig` 的 `antMatchers("/*").authenticated()` 拦截（该规则只匹配一级路径），请求直接进入 `BlogController.toWrite()`；该方法在渲染模板时需要读取当前登录用户信息，未登录时取到 null 导致 NPE |

## BUG-02 未登录访问博客详情返回 500

| 项 | 内容 |
|---|---|
| 缺陷编号 | BUG-02 |
| 所属模块 | 认证与权限 |
| 严重程度 | 严重 |
| 优先级 | 高 |
| 复现前置 | 未登录状态 |
| 复现步骤 | 1. Apifox 新建请求 `GET http://localhost:8080/blog/read/00000000000000000000000000000000`<br>2. 不携带 Cookie<br>3. 点击发送 |

## BUG-03 列表接口未被登录拦截

| 项 | 内容 |
|---|---|
| 缺陷编号 | BUG-03 |
| 所属模块 | 认证与权限 |
| 严重程度 | 一般 |
| 优先级 | 高 |
| 复现前置 | 未登录状态 |
| 复现步骤 | 1. Apifox 新建请求 `GET http://localhost:8080/blog/1/10`<br>2. 不携带 Cookie<br>3. 点击发送 |
| 预期结果 | 302 跳转登录页，与 `/blog` 保持一致 |
| 实际结果 | **200**，直接返回博客列表 HTML，可读取全部帖子标题与作者 |
| 影响 | 与一级路径 `/blog`（需要登录）的保护级别不一致，造成越权读取；同类问题存在于 `/question/{page}/{limit}` |
| 验证方法 | 对比执行 `GET /blog`（未登录）→ 302，与 `GET /blog/1/10`（未登录）→ 200，两者行为矛盾 |
| 初步根因 | `SecurityConfig.java` 中 `antMatchers("/*").authenticated()` 的 Ant 通配符 `*` 只匹配一级路径，`/blog/1/10` 含 3 段路径，规则未命中，请求被放行到控制器 |

## BUG-04 访问不存在资源时返回 500 或错误地返回 200

| 项 | 内容 |
|---|---|
| 缺陷编号 | BUG-04 |
| 所属模块 | 博客模块 |
| 严重程度 | 一般 |
| 优先级 | 中 |
| 复现前置 | 已登录 |
| 复现步骤 | 用例 A：`GET /blog/read/00000000000000000000000000000000`<br>用例 B：`GET /blog/delete/1/00000000000000000000000000000000` |
| 预期结果 | 用例 A：404 资源不存在；用例 B：404 或给出"博客不存在"提示，且不改变任何数据 |
| 实际结果 | 用例 A：**500 Internal Server Error**；用例 B：**200**，无任何错误提示，静默失败 |
| 影响 | 客户端无法区分"资源不存在"与"服务端故障"；删除不存在的数据仍返回成功，会误导调用方 |
| 初步根因 | `BlogController.read(String bid, Model model)` 中 `blogService.getOne(...)` 返回 null 后未做判空即放入 Model，模板渲染时对 null 取属性抛 NPE；`delete()` 直接调用 `remove()` 且不检查受影响行数 |

## BUG-05 分页参数无校验 + 删除操作使用 GET

| 项 | 内容 |
|---|---|
| 缺陷编号 | BUG-05 |
| 所属模块 | 博客模块 |
| 严重程度 | 一般 |
| 优先级 | 中 |
| 复现前置 | 已登录 |
| 复现步骤 | 用例 A：`GET /blog/0/10`（page 下越界）<br>用例 B：`GET /blog/1/999999`（limit 上越界）<br>用例 C：观察删除接口的方法类型 |
| 预期结果 | 用例 A：400 参数错误或自动纠正为第 1 页；用例 B：限制 limit 上限（如最大 100）；用例 C：删除应使用 POST/DELETE 并校验归属 |
| 实际结果 | 用例 A：**200**，返回第 1 页数据但无任何提示；用例 B：**200**，未做上限限制；用例 C：删除使用 **GET** 请求，且不校验当前用户是否为该帖作者 |
| 影响 | 1. 非法分页参数被静默接受，前端分页组件可能显示错误页码；<br>2. limit 过大时可被用于一次性拉取全量数据，存在数据爬取风险；<br>3. 用 GET 做删除违反 HTTP 语义，易被浏览器预取、爬虫或图片标签误触发，且缺少作者归属校验，属于越权删除风险 |
| 初步根因 | `BlogController.blogListPage(@PathVariable int page, @PathVariable int limit)` 未对入参做范围校验，直接构造 `Page<>(page, limit)` 交给 MyBatis-Plus；`delete` 映射为 `@GetMapping` 且未校验 uid 与当前登录用户是否一致 |

## 缺陷分布

| 维度 | 分布 |
|---|---|
| 按模块 | 认证与权限 3 条（BUG-01/02/03）、博客模块 2 条（BUG-04/05） |
| 按严重程度 | 严重 2 条、一般 3 条 |
| 按发现方式 | 接口自动化场景执行发现 5 条，源码定位确认根因 5 条 |
| 共性问题 | 3 条缺陷（BUG-01/02/03）根因相同，均指向 `SecurityConfig` 中 Ant 通配符使用不当，属于一处配置错误引发的多个表现 |

## 补充说明

上述缺陷均为被测系统**原始代码固有缺陷**，测试过程中未修改被测系统任何代码或配置，仅通过接口调用复现。缺陷等级判定依据：导致服务端异常（500）的定为「严重」，返回码不符合语义或存在越权风险的定为「一般」。
