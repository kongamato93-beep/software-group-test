# 接口测试用例表

> 被测系统：狂神の小社区（kuang_simple_bbs），`http://localhost:8080`
> 测试工具：Apifox 桌面版
> 用例总数：14 条（全部已执行），全部纳入 Apifox 自动化测试场景
> 用例设计方法：等价类划分法、边界值分析法、场景法、错误推测法

## 一、用例设计思路

| 方法 | 应用点 |
|---|---|
| 场景法 | 场景一按「登录 → 浏览列表 → 发帖 → 查看详情 → 评论 → 删除」串成一条完整业务链，验证接口间的数据传递 |
| 等价类划分法 | 路径参数 `page` / `limit` / `bid` 划分为有效等价类（正常值）与无效等价类（0、超大值、不存在的 id） |
| 边界值分析法 | `page=0`、`limit=999999` 取分页参数的边界与越界值 |
| 错误推测法 | 未登录直接访问受限接口、访问不存在的资源，推测服务端是否做了防御 |

## 四、关于「断言值」与「用例状态」的说明

Apifox 自动化场景中，异常路径用例（TC-API-007 ~ TC-API-009、TC-API-011 ~ TC-API-014）的断言对象配置为**当前实际返回码**，目的是把现状固化为回归基线——一旦开发修复缺陷、返回码发生变化，脚本会立刻报警。

但**用例的预期值仍以正确业务行为为准**，实际返回与预期不符即判定「不通过」，差异全部登记在《03-接口测试缺陷记录.md》中，未做任何美化。这也是两个场景在 Apifox 里显示为全绿、而本用例表存在 7 条不通过的原因。
